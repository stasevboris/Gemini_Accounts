# Команда агентов

Команда — несколько отдельных агентских сессий, работающих над общей задачей. У каждой сессии своя история, роль, модель и выбранный аккаунт. Аккаунт предоставляет доступ и квоту; сам по себе он не становится агентом. Несколько агентов на одном аккаунте делят его квоту и отправляют запросы по очереди.

## Запуск

1. Открой вкладку **Команда**. Состав и настройки можно подготовить и сохранить даже при выключенном режиме команды.
2. Нажми **Обновить аккаунты**. В состав доступны включённые аккаунты с опубликованными текстовыми моделями. Список моделей шлюза не гарантирует доступ по тарифу: ошибки провайдера отображаются в журнале.
3. Выбери размер команды и нажми **Сформировать состав**. В каждой строке можно изменить аккаунт, модель, роль и инструкции. Например, смешать Google Gemini и ChatGPT с `gpt-6-luna`.
4. Назначь ровно одного координатора и хотя бы одного исполнителя. Отдельные проверяющие необязательны: исполнители могут проверять результаты друг друга. При одном участнике отключи взаимную проверку.
5. Раскрой **Тип задачи, лимиты и доступ**. Для кода выбери папку проекта. Для исследований разреши поиск и чтение сайтов.
6. Опиши результат и критерии готовности. Рядом с кнопками поставь галочку **Включить команды агентов** и нажми **Запустить задачу**. Если запуск недоступен, подсказка над кнопкой объяснит причину.

Сохранение настроек не запускает задачу. После перезапуска приложения команды автоматически не продолжаются.

При временной ошибке агент учитывает `Retry-After` и паузу восстановления конкретного аккаунта в шлюзе. На доске появится **Ожидает повтора**, а в чате — сообщение об ожидании. Остановка и общий предел времени действуют и во время этой паузы. Ошибки доступа и оплаты, например 401/402/403, повторными запросами не исправляются: выбери доступный аккаунт или убери его из состава. Учётная запись участника сама не заменяется другой.

## Вызов из существующего чата Claude

Сначала настрой состав во вкладке **Команда**, включи функцию и нажми **Сохранить настройки**. Выбранная папка, разрешения и лимиты применяются и к запускам из чата. Затем нажми **Подключить команду к Claude**. Если клиент ещё не подключён к шлюзу, сначала подключи его в разделе **Подключения**. После завершения текущей работы перезапусти Claude, чтобы он загрузил новые пункты и инструменты.

Доступны два способа:

- **Модель «Команда агентов».** Выбери её в списке моделей существующего чата и отправь задачу. Шлюз передаст команде историю, которую Claude включил в этот запрос, и вернёт общий результат в тот же чат. После ответа можно выбрать обычную модель и продолжить разговор.
- **MCP «gemini-accounts-team».** Оставь текущую модель и попроси её передать задачу команде через `team_start`, приложив нужный контекст разговора. `team_config` показывает сохранённый состав и разрешения; `team_status` и `team_wait` дают ход работы и результат; `team_stop` останавливает запуск. Клиент может запросить разрешение на использование инструментов. Если модель не вызывает инструменты, выбери способ через отдельную модель команды.

Команда не получает автоматически другие чаты из боковой панели или всю историю проекта Claude. При вызове через MCP контекст передаёт вызывающая модель. Локальные файлы она читает из папки, выбранной в менеджере. Для продолжения работы над дипломом укажи эту папку и сформулируй задачу в текущем чате.

Запуски из чата видны во вкладке **Команда**: доступны доска, журнал, остановка и экспорт. Одновременно выполняется одна команда. Закрытие менеджера отменяет только запуск, начатый самим менеджером; команда, вызванная из чата, работает в локальном шлюзе. После перезапуска шлюза прерванная задача автоматически не продолжается.

## Большие файлы и документы

`read_file` читает текст, код и DOCX по строкам; `read_text_chunk` — по смещению в символах. Следующую часть указывает `next_line` или `next_offset`. `read_document` извлекает текст PDF по страницам и DOCX с таблицами. `search_files` ищет текст внутри проекта. Ограничение размера исходного файла — 50 МБ; сканы PDF без текстового слоя требуют отдельного OCR. Старый формат DOC нужно сначала преобразовать в DOCX или PDF.

Полная переданная история чата доступна через `read_chat_context`. При переполнении рабочих историй агент получает краткое продолжение; исходные сообщения остаются в зашифрованной истории запуска. Сжатие расходует общий бюджет запросов.

## Как участники взаимодействуют

Координатор разбивает запрос на отдельные подзадачи. Исполнители работают с собственными историями, читают общую доску и могут передавать находки или вопросы другим участникам. Затем другой агент проверяет каждый результат. Отклонённая работа отправляется автору на доработку, если остались раунды проверки. Координатор объединяет результаты.

Участник не одобряет собственную работу. Неуспешная или не пройденная проверка даёт статус **Требует проверки**, а не **Завершено**. Задача, остановленная лимитом или кнопкой остановки, также не считается завершённой.

Сто участников полезны только для задач, которые достаточно хорошо делятся на независимые части. Это не обещание ускорения в сто раз. Всеобщая проверка «каждый проверяет всех» быстро увеличивает расходы на сообщения; программа использует назначенные независимые проверки.

## Лимиты и разрешения

| Настройка | Что ограничивает |
| --- | --- |
| Размер команды | До 100 сессий с собственными ролями и историями |
| Одновременные запросы | Максимум запросов к провайдерам одновременно; на одном аккаунте — один запрос |
| Максимум запросов | Общий предел, включая планирование, инструменты, проверки и итог |
| Время | Время всего запуска; при достижении предела работа отменяется |
| Шаги | Максимум ходов модели с инструментами за один этап |
| Повторы | 0–3 повторных запроса при временных ошибках, включая 502; они входят в общий бюджет запросов |
| Токены на ответ | Максимальная длина одного ответа; фактический учёт зависит от данных провайдера |
| Раунды проверки | Число независимых проверок с возможной доработкой; 0 отключает проверку |

Обычный режим поддерживает поиск публичных источников, чтение сайтов, анализ и тексты. Режим проекта добавляет чтение выбранной папки. Файлы авторизации и служебные папки с учётными данными не выдаются инструментам чтения.

Исполнители и проверяющие не записывают файлы проекта. Запись доступна координатору на итоговом этапе после успешных проверок, если ты включил соответствующий флажок. Перед записью проверяется хеш текущего файла, прежнее содержимое сохраняется в зашифрованной истории. При выключенной записи команда готовит предложения и итоговый текст.

Выполнение команд включается отдельно и доступно координатору в том числе во время анализа и проверки. Команды работают с правами текущего пользователя и могут менять файлы самостоятельно; для отслеживания их изменений используй Git. Один процесс команды ограничен 60 секундами.

## История и остановка

На доске видны подзадачи и проверки; ниже — итог, журнал и история запусков. Результат можно экспортировать в Markdown. История хранится локально в зашифрованном виде. При выходе из приложения запуск, начатый в нём, отменяется; сворачивание в трей сохраняет работу. Запусками из чата управляет шлюз.

Для точного выбора аккаунтов программа временно публикует уникальные маршруты моделей. Исходные маршруты обычных клиентов сохраняются. После завершения или остановки временные префиксы восстанавливаются. Если приложение аварийно закрыто, запись восстановления остаётся локально; следующий запуск команды сначала выполняет восстановление. Аккаунты с собственным пользовательским префиксом требуют отдельного выбора и не перенастраиваются автоматически.

Поддерживаются Google, ChatGPT и Claude. Если проверяющий недоступен, команда пытается использовать другой независимый аккаунт. При достижении лимита инструментов агент получает завершающий ход без инструментов и сохраняет подготовленные предложения и незавершённые пункты. Общие лимиты запросов и времени по-прежнему действуют.
