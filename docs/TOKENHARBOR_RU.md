# API-ключи и подписки

[English](API_KEYS.md) · **Русский** · [Вернуться к README](../README_RU.md)

Вкладка **API-ключи** позволяет добавить несколько ключей TokenHarbor или API,
совместимого с Anthropic. Для каждого задаются название, HTTPS-адрес API и ID
моделей (по одному в строке). Кнопка загрузки каталога добавляет выбранную модель;
можно повторить выбор или вписать ID вручную. При редактировании пустое поле ключа
сохраняет старый ключ. Есть приостановка и удаление профиля.

Модели ключей доступны в Claude Desktop рядом с Google Gemini и Google Claude,
с названием `API · название ключа · модель`. Они имеют отдельные идентификаторы
`api/<профиль>/<модель>` и не меняют настройки моделей подписки или маршрутизацию
Google-аккаунтов. Два ключа к одной модели отображаются отдельно. После изменения
ключей переоткройте Claude Desktop для обновления его меню моделей.

Ключи хранятся в зашифрованном Windows DPAPI файле `api-keys.dpapi` в локальном
каталоге данных приложения. Они не попадают в исходники, каталог моделей,
диагностику, настройки клиентов или установщик. Прежний `tokenharbor-key.dpapi`
читается как исходный профиль; при первом сохранении он переносится в новый
реестр. Удалённый профиль не появляется снова из старого файла.

Статистика каждого ключа сохраняется отдельно: ответы, ошибки, входные и выходные
токены, средняя длительность, последняя модель и код ответа. Повторные попытки
провайдера учитываются. Входные токены включают кэш, если провайдер сообщает его.
Баланс и процент оставшейся квоты не вычисляются из этих счётчиков. Содержимое
сообщений не сохраняется. Отменённая передача ответа отмечается как ошибка 499.

Шлюз сохраняет формат запроса: `/v1/messages` остаётся Anthropic,
`/v1/chat/completions` и `/v1/responses` остаются OpenAI (TokenHarbor поддерживает
оба формата). Обычный Anthropic API использует `x-api-key`. API, поддерживающий
только OpenAI, нельзя подключить к Claude Desktop этим способом: нужен адаптер
формата. Квоты Google-аккаунтов не блокируют API-ключи; собственные HTTP 429
обрабатываются отдельно. Смена ключа не требует перезапуска шлюза.

Проверки: `python -m unittest tests.test_api_keys tests.test_tokenharbor`.
Документация TokenHarbor: https://tokenharbor.ai/docs/api/curl
# Проверка подключения

В редакторе ключа появилась проверка первой модели двумя короткими запросами:
напрямую к провайдеру и через локальный шлюз. Проверка черновика не сохраняет
изменения; существующие ключи продолжают работать. При ошибке исходное
зашифрованное хранилище восстанавливается. Изменённое подключение по умолчанию
проверяется перед сохранением; эту проверку можно отключить для сохранения
подключения, пока провайдер недоступен.
