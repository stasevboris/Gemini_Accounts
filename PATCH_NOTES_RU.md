# Патч совместимости Claude Desktop / Agent SDK

Основа: Gemini Accounts v1.3.3, CLIProxyAPI v8.0.16.
Версия сборки: 1.3.3+desktop-compat.2.

## Найденная причина

На сохранённых запросах Desktop Google возвращал generic HTTP 429 RESOURCE_EXHAUSTED при наличии системного блока:

`You are a Claude agent, built on Anthropic's Claude Agent SDK.`

Та же учётная запись отвечала HTTP 200 на тот же запрос после удаления только этой строки. Это воспроизведено на Gemini и Claude Opus. Сброс локального cooldown сам по себе проблему не устранял.

## Изменение

Локальный шлюз удаляет только указанную служебную строку идентификации SDK из начала системного текстового блока для моделей Gemini/Claude. Он сохраняет инструкции задачи, пользовательские сообщения, инструменты, thinking, effort и лимит выходных токенов. Цитаты в пользовательских сообщениях не меняются. В техническом журнале появляется событие `client_compatibility`; текст запросов в него не записывается.

Исправление действует на POST /v1/messages через локальный шлюз (обычно 127.0.0.1:8317). Прямое обращение клиента к нативному порту 8318 его обходит.

Удалён пробный патч автоматического сброса cooldown: он делал короткие диагностические запросы при чтении квот, но не исправлял запросы Desktop. Ограничения реальной серверной квоты сохраняются. У одного из двух аккаунтов действительно исчерпано недельное окно Claude; у другого доступна квота.

## Проверки

100 автоматических тестов прошли. Через исправленный шлюз повторены сохранённые запросы Desktop с исходными параметрами и заголовками:
- Opus: запрос заголовка — HTTP 200, текст и message_stop.
- Gemini: полный запрос с 38 инструментами — HTTP 200, текст и message_stop.
- Opus: тот же полный запрос с 38 инструментами — HTTP 200, текст и message_stop.

Последние проверки полного запроса заняли примерно 5 секунд. После установки сборки повторены полные запросы через установленный шлюз: Gemini и Opus завершились HTTP 200 с текстом и message_stop. Пользователь подтвердил ответы в самом окне Claude Desktop.

## Файлы

- desktop_compat.py — узкое исправление служебного блока.
- quota_queue.py — применение исправления и событие диагностики.
- runtime.py / installer.py — версия сборки.
- updater.py — сравнение локальной версии с upstream без build metadata.
- tests/test_desktop_compat.py, tests/test_quota_queue.py, tests/test_updater.py — проверки.
- dist/GeminiAccounts-Setup.exe — установщик.

Регион аккаунта и подписка не менялись. Исправление не снимает серверные лимиты и не доказывает отсутствие иных региональных ограничений. Переустановка upstream-сборки заменит локальный патч.

Исходники предыдущих изменений сохранены в build/source-before-desktop-fix. Копия исходников upstream v1.3.3 — build/source-v1.3.3.

## Проверка генерации кода

Обе модели получили одну задачу: написать statlog.py для анализа JSONL-журнала, с валидацией HTTP-статусов и обработкой больших файлов построчно. Сохранён контекст Desktop с инструментами. Обе модели вернули полный код без вызовов инструментов, HTTP 200 и завершённый поток примерно за 12 секунд.

Исходный код прочитан перед запуском. Проверки чтения из файла и stdin, пустого ввода и отсутствующего файла прошли для обеих моделей. Набор данных включает bool вместо status, статусы вне диапазона, некорректный JSON, не-объекты и пустые строки. Артефакты: build/model-check/gemini_statlog.py, opus_statlog.py, prompt.txt, verification.json.

Копии установленных до патча EXE и installation.json сохранены в build/installed-before-desktop-compat. Аккаунты, ключи и конфигурация при замене EXE не менялись. Подробное нативное журналирование запросов выключено.

## Удаление аккаунтов

Добавлены Remove в строке каждого аккаунта (в том числе при свёрнутых деталях) и Remove account в его карточке. Диалог показывает конкретный аккаунт перед удалением сохранённого входа. Удаление выполняется через management API с единственным полем name. Остальные входы сохраняются. Локальная метка, данные проверки и таймеры удалённого аккаунта очищаются; при удалении выбранного аккаунта восстанавливается маршрутизация оставшихся.

Аккаунт account@example.com удалён по запросу владельца; его auth-файл отсутствует. Остальные три входа сохранены. 106 автоматических тестов прошли, включая отмену диалога и удаление выбранного/последнего аккаунта. Обновлён установленный менеджер и установщик; работающий шлюз не перезапускался.
